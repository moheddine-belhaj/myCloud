# auth

Everything the auth service needs to talk to its database. Business logic (register, login, TOTP) is added on top in later PRs.

- `migrations/` – the schema as embedded goose SQL files.
- `queries/` – hand-written SQL, one file per table.
- `store/` – Go code **generated by sqlc** from the two folders above. Never edit by hand.

Flow: change a migration or query → run `sqlc generate` (see `backend/sqlc.yaml`) → use the typed functions in `store/`. CI runs `sqlc diff` and fails if the generated code is stale.

Tables: `users` (argon2id hash, lowercase email, role), `invites` (single-use, only the SHA-256 of the code is stored), `sessions` (only the SHA-256 of the cookie token is stored, so a database leak does not leak logins).
